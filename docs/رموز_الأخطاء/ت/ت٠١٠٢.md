# ت٠١٠٢: مكتبة وقت التشغيل غير موجودة

## الوصف

كل ملف تنفيذي تنتجه الترجمة الأصلية يُربَط بمكتبة وقت التشغيل الساكنة
`libtrq.a` (أو `trq.lib` على ويندوز)، وفيها دوال `trq_` التي يستدعيها الكود
المولَّد للطباعة والنصوص والمصفوفات والحساب.

يظهر هذا الخطأ حين لا يجد المترجم هذه المكتبة في أيٍّ من مواضع البحث.

## سبب الخطأ

السبب الأشيع: المكتبة **لم تُبنَ**. حزمة `tarqeem-runtime` مستقلة تحت
`runtime-rs/`، وهي ليست ضمن الأعضاء الافتراضيين لمساحة العمل، فـ`cargo build`
المجرَّد لا يبنيها.

أسباب أخرى:

1. **بناء ناقص**: بُني المترجم ولم تُبنَ المكتبة معه
2. **تثبيت ناقص**: نُسخ الملف التنفيذي دون `lib/libtrq.a` بجانبه
3. **`CARGO_TARGET_DIR` مخصص**: المكتبة في مجلد لا يبحث فيه المترجم
4. **مسار صريح خاطئ**: `TARQEEM_RUNTIME_PATH` يشير إلى ملف غير موجود

## مثال الخطأ

```
خطأ[ت٠١٠٢]: لم يتم العثور على مكتبة وقت التشغيل libtrq.a
  |
  = المواضع التي بُحث فيها:
  |   /Users/x/tarqeem/target/release/libtrq.a
  |   /Users/x/tarqeem/target/release/runtime/libtrq.a
  |   /Users/x/.tarqeem/lib/libtrq.a
  |   /usr/local/lib/tarqeem/libtrq.a
  |
  = ابنِها بـ: cargo build -p tarqeem-runtime --release
```

## الحل

### الحل ١: ابنِ المكتبة

```bash
cargo build -p tarqeem-runtime --release
```

استخدم البناء نفسه الذي بُني به المترجم — مكتبةُ `debug` لا تُقرَن بمترجم
`release` والعكس:

```bash
cargo build -p tarqeem-runtime          # للتطوير
cargo build -p tarqeem-runtime --release
```

أو ابنِ مساحة العمل كاملة، فتُبنى الاثنتان معاً:

```bash
cargo build --release --workspace
```

### الحل ٢: تحديد المسار صراحةً

يتقدَّم `TARQEEM_RUNTIME_PATH` على كل مواضع البحث، وهو المخرج حين تكون المكتبة
في موضع غير معتاد:

```bash
export TARQEEM_RUNTIME_PATH="/مسار/إلى/libtrq.a"
tarqeem compile برنامج.ترقيم
```

### الحل ٣: أعد التثبيت

إن كنت تشغّل نسخة مثبَّتة:

```bash
make install       # ينسخ المترجم والمكتبة معاً
```

## مواضع البحث

يبحث المترجم بالترتيب التالي، وأول موجود يفوز:

| # | الموضع |
|---|--------|
| ١ | `TARQEEM_RUNTIME_PATH` |
| ٢ | `libtrq.a` بجوار الملف التنفيذي |
| ٣ | `runtime/`، `../runtime/`، `../lib/` بالنسبة للملف التنفيذي |
| ٤ | المسار المُضمَّن وقت بناء المترجم |
| ٥ | `target/<البناء>/` في مساحة العمل |
| ٦ | `TARQEEM_HOME/lib` |
| ٧ | `runtime/` في المجلد الحالي |
| ٨ | `~/.tarqeem/lib` |
| ٩ | مسارات النظام |

**الترتيب مقصود**: المكتبة المبنيّة بجوار المترجم تتقدَّم على أي نسخة مثبَّتة،
حتى لا يُربَط بناءٌ حديث بمكتبة قديمة صامتةً. لعرض المكتبة المختارة فعلاً:

```bash
tarqeem compile برنامج.ترقيم -v
```

## لماذا خطأ لا تحذير

كانت المكتبة المفقودة تُتجاهَل بصمت، فيمضي الربط بلا مكتبة ويفشل بعدها بخطأ
رموز غير معرَّفة يذكر رموزاً داخلية:

```
Undefined symbols for architecture arm64:
  "_trq_string_to_int_checked", referenced from: ...
```

وهي رسالة لا تدل على السبب. الرفض المبكر يذكر السبب ومواضع البحث والأمر الذي
يصلحه.

## ملاحظة عند فحص الرموز

`nm -g` يقرأ مكتبة `release` فارغةً، لأن `lto = true` يترك أعضاءها شفرةً وسيطة
لا كائنات أصلية. استخدم `strings` أو مكتبة `debug` عند التحقق من وجود رمز.
