# ص٠٦٠١: رمي قيمة ليست استثناءً

## الوصف

هذا الخطأ يحدث عند استخدام `ارمِ` مع قيمة ليست نسخة من الصنف `استثناء` ولا من أحد أصنافه الفرعية.

الأنواع الأولية — `نص`، `عدد`، `عدد_عشري`، `منطقي` — **لا يمكن رميها**، وكذلك أي صنف لا يرث `استثناء`.

## سبب الخطأ

معامل الالتقاط في `التقط (خ)` نمطه دائماً `استثناء`، وهذا ما يمنح `خ.رسالة` معناها. لو جاز رمي نص أو عدد، لما كان لدى كتلة `التقط` ما تعتمد عليه: كل معالج سيضطر لفحص نوع ما التقطه قبل قراءة أي شيء منه.

توحيد الأصل في `استثناء` يجعل كل استثناء يحمل سبب حدوثه في `رسالة`، ويجعل `التقط` قابلة للكتابة مرة واحدة لكل الحالات.

> **ملاحظة**: الكلمة `خطأ` ليست اسم صنف — هي القيمة المنطقية (نقيض `صحيح`). صنف الاستثناء الأساسي اسمه `استثناء`، وهو **معرَّف تلقائياً** في كل برنامج بلا حاجة إلى `استورد`.

## مثال الخطأ

```tarqeem
بسم_الله
حاول {
    ارمِ "لا يمكن القسمة على صفر"    // ❌ نص، ليس استثناءً
} التقط (خ) {
    اطبع(خ.رسالة)
}
الحمد_لله
```

## الحل

### الحل ١: لُفَّ الرسالة في `استثناء`

```tarqeem
بسم_الله
حاول {
    ارمِ جديد استثناء("لا يمكن القسمة على صفر")    // ✅ صحيح
} التقط (خ) {
    اطبع(خ.رسالة)
}
الحمد_لله
```

### الحل ٢: عرّف صنف استثناء خاصاً بك

عندما تريد تمييز نوع الخطأ — أو حمل بيانات إضافية معه — ورّث `استثناء`:

```tarqeem
بسم_الله
صنف استثناء_قسمة يرث استثناء {
    منشئ(رسالة: نص) {
        الأصل(رسالة)
    }
}

دالة قسمة(أ: عدد، ب: عدد) -> عدد {
    إذا (ب == 0) {
        ارمِ جديد استثناء_قسمة("لا يمكن القسمة على صفر")    // ✅ صحيح
    }
    أرجع أ / ب
}
الحمد_لله
```

## حالات شائعة

### الحالة ١: صنف لا يرث `استثناء`

```tarqeem
صنف شخص {
    عام الاسم: نص
}

ارمِ جديد شخص()    // ❌ 'شخص' لا يرث 'استثناء'
```

الحل: أضف `يرث استثناء` إذا كان الصنف فعلاً يمثل حالة خطأ، وإلا فارمِ استثناءً يصف المشكلة بدل رمي الكائن نفسه.

`استثناء` معرَّف تلقائياً؛ إعادة تعريفه تُنتج [ص٠٦٠٢](ص٠٦٠٢.md).
