# و٠٣٠١: تبعية دائرية

## الوصف

هذا الخطأ يحدث عندما تستورد وحدتان أو أكثر بعضهما البعض بشكل دائري، مما يُنشئ حلقة لا نهائية من الاستيرادات.

التبعيات الدائرية تمنع المترجم من تحديد ترتيب التحميل الصحيح للوحدات.

## سبب الخطأ

السيناريوهات الشائعة:

1. **دورة مباشرة**: وحدة أ تستورد ب، وب تستورد أ
2. **دورة غير مباشرة**: أ ← ب ← ج ← أ
3. **تصميم غير صحيح**: فصل الكود بطريقة تُنشئ تبعيات متبادلة

## مثال الخطأ

**ملف: مستخدم.ترقيم**
```tarqeem
بسم_الله

استورد { طلب } من "./طلب"

صدّر صنف مستخدم {
    اسم: نص
    طلبات: مصفوفة<طلب>
}

الحمد_لله
```

**ملف: طلب.ترقيم**
```tarqeem
بسم_الله

استورد { مستخدم } من "./مستخدم"  // ← دورة!

صدّر صنف طلب {
    رقم: عدد
    صاحب: مستخدم
}

الحمد_لله
```

**الرسالة**:
```
خطأ[و٠٣٠١]: تبعية دائرية بين الوحدات
  --> مستخدم.ترقيم:3:1
  |
  = سلسلة التبعيات:
    مستخدم.ترقيم
    └── طلب.ترقيم
        └── مستخدم.ترقيم  ← دورة!
  |
  = أعد هيكلة الكود لكسر الدورة
```

## الحل

### الحل ١: إنشاء وحدة أنواع مشتركة

انقل الأنواع المشتركة إلى وحدة منفصلة:

**ملف: أنواع.ترقيم**
```tarqeem
بسم_الله

// الأنواع الأساسية بدون تبعيات
صدّر صنف معرف_مستخدم {
    قيمة: عدد
}

صدّر صنف معرف_طلب {
    قيمة: عدد
}

الحمد_لله
```

**ملف: مستخدم.ترقيم**
```tarqeem
بسم_الله

استورد { معرف_مستخدم، معرف_طلب } من "./أنواع"

صدّر صنف مستخدم {
    معرف: معرف_مستخدم
    اسم: نص
    طلبات: مصفوفة<معرف_طلب>  // معرّفات بدلاً من كائنات
}

الحمد_لله
```

**ملف: طلب.ترقيم**
```tarqeem
بسم_الله

استورد { معرف_مستخدم، معرف_طلب } من "./أنواع"

صدّر صنف طلب {
    معرف: معرف_طلب
    رقم: عدد
    صاحب: معرف_مستخدم  // معرّف بدلاً من كائن
}

الحمد_لله
```

### الحل ٢: استخدام التبعية في اتجاه واحد

اجعل التبعيات تسير في اتجاه واحد فقط:

```
     أنواع_أساسية
           ↑
    ┌──────┴──────┐
    ↑             ↑
 مستخدم        طلب
    ↑             │
    └─────────────┘  ← هذا ممنوع!
```

```
     أنواع_أساسية
           ↑
    ┌──────┴──────┐
    ↑             ↑
 مستخدم        طلب
                  ↑
             خدمات
```

### الحل ٣: نقل الدوال إلى وحدة خدمات

**ملف: خدمات.ترقيم**
```tarqeem
بسم_الله

استورد { مستخدم } من "./مستخدم"
استورد { طلب } من "./طلب"

// الدوال التي تحتاج كلا النوعين
صدّر دالة احصل_طلبات_مستخدم(م: مستخدم) -> مصفوفة<طلب> {
    // ...
}

صدّر دالة احصل_صاحب_طلب(ط: طلب) -> مستخدم {
    // ...
}

الحمد_لله
```

### الحل ٤: استخدام الميثاق (Interface)

**ملف: مواثيق.ترقيم**
```tarqeem
بسم_الله

صدّر ميثاق صاحب_طلب {
    دالة احصل_اسم() -> نص
}

الحمد_لله
```

**ملف: طلب.ترقيم**
```tarqeem
بسم_الله

استورد { صاحب_طلب } من "./مواثيق"

صدّر صنف طلب {
    رقم: عدد
    صاحب: صاحب_طلب  // ميثاق بدلاً من صنف محدد
}

الحمد_لله
```

## كيفية اكتشاف التبعيات الدائرية

### رسم خريطة الاستيرادات

```
الملف الحالي: رئيسي.ترقيم
    ├── مستخدم.ترقيم
    │   └── طلب.ترقيم
    │       └── مستخدم.ترقيم  ← مكرر = دورة!
    └── خدمات.ترقيم
        └── ... (آمن)
```

### البحث عن الأنماط المشبوهة

- صنفان يحتويان على مراجع لبعضهما
- دالتان تستدعيان بعضهما من وحدتين مختلفتين
- ثوابت متبادلة بين وحدتين

## أفضل الممارسات

1. **تصميم هرمي**: اجعل التبعيات تتدفق في اتجاه واحد
2. **وحدات أنواع منفصلة**: ضع الأنواع المشتركة في وحدة أساسية
3. **مبدأ المسؤولية الواحدة**: كل وحدة مسؤولة عن شيء واحد
4. **تجنب الإشارات المتبادلة**: استخدم المعرّفات بدلاً من الكائنات
